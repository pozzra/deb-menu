SCOPE
-----
This file documents every function and method defined in the Rxaa iOS tweak
and its embedded HTML/JavaScript catalog.

It does NOT document the thousands of internal functions in libRAACHEAT.so.
That is separate native reverse-engineering work. This is the UI/build layer:
the floating icon, the native Rxaa list, the All Features browser, the ON/OFF
switches, the Get Code catalog WebView, and the retry/install flow.

SAFETY NOTE
-----------
Rxaa is UI-only. The AimLock/ESP/Radar switches save a boolean in
NSUserDefaults and change a label. The All Features switches do the same for
catalog entries. They do not hook a game, read/write game memory, or perform
aimbot/ESP behavior.

GLOBAL STATE (Tweak.x)
----------------------
gOverlayWindow
  The full-screen UIWindow at UIWindowLevelAlert + 100 that hosts the Rxaa menu.
  Created once per process by RAACHEATInstallOverlay. It is hidden whenever the
  menu is closed, so it cannot intercept game touches outside the button.

gButtonWindow
  A separate 52x52 UIWindow at UIWindowLevelAlert + 101 that hosts only the
  floating button. While the menu is closed this is the only Rxaa window that
  is visible, so the game remains clickable everywhere except the button.

gFloatButton
  The 52x52 draggable button. Uses menu_icon.png/menu_image.jpg as its
  background image, or the letter "R" if no icon file is found. Its position is
  saved in NSUserDefaults and clamped to the screen safe area.

gMenuNav
  The currently presented UINavigationController containing the Rxaa list.
  nil when no menu is open. Set back to nil after dismissal.

gOpenGesture
  Four-finger triple-tap recognizer installed on the host app window. It is a
  fallback way to open Rxaa if the floating button is covered or off-screen.

gGestureWindow
  The UIWindow that currently owns gOpenGesture. If the app changes windows,
  the old recognizer is removed and a new one is installed.

gPreviousKeyWindow
  The app window that was key before Rxaa opened. The overlay becomes key while
  the menu is visible; this window is restored when the menu closes.

gInstallAttempts
  Retry counter for processes whose UIApplication/UIWindowScene is not ready.
  The installer gives up after 41 attempts (about 61.5 seconds), and the
  lifecycle observer resets it when the app becomes active.

STARTUP / CALL FLOW
-------------------
1. MobileSubstrate/ElleKit loads the dylib and runs %ctor.
2. %ctor installs lifecycle observers, waits 1.5 seconds, then calls
   RAACHEATTryInstall.
3. RAACHEATTryInstall calls RAACHEATInstallOverlay.
4. RAACHEATInstallOverlay waits for an active UIWindowScene. It uses a legacy
   window fallback only when the app already has windows but no scene.
5. It creates RAACHEATRootController for the full-screen menu, a separate
   RAACHEATButtonController in a 52x52 button window, and installs the
   four-finger triple-tap fallback gesture on the host window.
6. Tapping the button sends -raacheatOpen to RAACHEATButtonController; the
   fallback gesture sends -raacheatOpen to RAACHEATRootController.
7. Both -raacheatOpen methods call RAACHEATOpenPanel.
8. RAACHEATOpenPanel presents RXAAMenuViewController inside a
   UINavigationController.
9. The table shows AimLock/ESP/Radar switches, Get Code, All Features,
   Apply All (Demo), Reset All (Demo), Python Engine, and Telegram.
10. Tapping All Features pushes RXAACatalogFeatureViewController, which uses
    menu_catalog.json or the embedded 116-entry fallback.
11. Tapping Get Code pushes RXAACatalogViewController, which loads
    index.html into a WKWebView.
12. Tapping Python Engine shows terminal instructions for mod_menu.py; tapping
    Telegram opens https://t.me/kun_amra.
13. Close dismisses the navigation controller, clears gMenuNav, hides the
    full-screen overlay, restores the game key window, and re-shows the button.
14. UIApplicationDidBecomeActiveNotification, UISceneDidActivateNotification,
    UIWindowDidBecomeKeyNotification, and UIWindowDidBecomeVisibleNotification
    reattach the windows, keep the button visible while the menu is closed, and
    re-key only the full-screen menu while it is open.

1. RAACHEATPassThroughView -hitTest:withEvent:
   Signature: - (UIView *)hitTest:(CGPoint)point withEvent:(UIEvent *)event
   Location: Tweak.x
   Class:    RAACHEATPassThroughView

   Purpose
     Keep the full-screen overlay from swallowing touches if it is visible.
     The floating button now lives in its own 52x52 window, and the full-screen
     overlay is hidden while the menu is closed. This view remains as a safety
     fallback and lets the overlay pass through empty touches.

   Parameters
     point - touch point in the view's coordinate system.
     event - the UIEvent being dispatched.

   Returns
     nil when the hit view is the root view itself.
     The actual subview when the touch lands on the presented menu or another
     interactive subview.

   Behavior
     Calls [super hitTest:withEvent:]. If the result is self, returns nil;
     otherwise returns the subview. This keeps empty overlay areas from
     swallowing touches while the menu is open.

   Side effects
     None.

   Notes
     When the native Rxaa menu is presented as a full-screen modal, the modal
     has its own opaque view and handles its own touches.

6. RAACHEATOpenPanel
   Signature: static void RAACHEATOpenPanel(void)
   Location: Tweak.x

   Purpose
     Open the native Rxaa list. The name is historical; this now presents the
     navigation controller, not the old WebView panel.

   Parameters
     None.

   Returns
     void.

   Guards
     - Returns if gOverlayWindow is nil.
     - Returns if the overlay root has no view controller.
     - If gMenuNav is already presented, returns.
     - If gMenuNav is stale (not the presented controller), clears it and
       continues.
     - Returns if the overlay root is already presenting another controller.

   Behavior
     1. Logs "[Rxaa] opening menu".
     2. Calls RAACHEATRefreshOverlayBounds so the overlay and root view match
        the current UIWindowScene, then shows the overlay at
        UIWindowLevelAlert + 100 and hides the small button window before
        presenting.
     3. Saves the current app key window in gPreviousKeyWindow via
        RAACHEATKeyWindowForScene(nil). If no key window is found, uses the
        first non-overlay, non-button app window.
     4. Calls [gOverlayWindow makeKeyAndVisible] so presentation/touches work
        reliably while the menu is open. The button window stays hidden.
     5. Creates RXAAMenuViewController with UITableViewStyleGrouped.
     6. Wraps it in a UINavigationController.
     7. Sets UIModalPresentationFullScreen, a cover-vertical transition,
        status-bar capture, and the Rxaa background color.
     8. Presents it from the overlay window's root controller.
     9. In the presentation completion, clears gMenuNav, hides the overlay,
        restores the previous key window, and re-shows the button if the
        navigation controller did not actually become the presented
        controller.

   Side effects
     Sets gMenuNav to the new navigation controller. The controller is
     dismissed later by -closeMenu, which hides the full-screen overlay,
     restores the game key window, and shows the button window again.

   Called by
     RAACHEATButtonController -raacheatOpen (floating button tap) and
     RAACHEATRootController -raacheatOpen (four-finger fallback gesture).

9c. RAACHEATButtonController -raacheatPan:
    Signature: - (void)raacheatPan:(UIPanGestureRecognizer *)pan
    Location: Tweak.x
    Class:    RAACHEATButtonController

    Purpose
      Let the user drag the button window anywhere on screen.

    Parameters
      pan - the attached UIPanGestureRecognizer.

    Returns
      void.

    Behavior
      - On Began: records the window center and the gesture's location in the
        full-screen overlay's coordinate space; fades the button slightly.
      - On Changed: computes the new center from the drag delta and clamps it
        with RAACHEATClampFloatButtonCenter.
      - On Ended/Cancelled/Failed: clamps again, saves the normalized position
        with RAACHEATSaveFloatButtonPosition, and restores full opacity.
      - Uses a tap gesture for opening, so dragging does not accidentally open
        the menu.

    Side effects
      Moves gButtonWindow and writes NSUserDefaults rxaa.float.centerX/Y. Does
      not touch game memory or process state.

26. RAACHEATInstallOverlay
    Signature: static void RAACHEATInstallOverlay(void)
    Location: Tweak.x

    Purpose
      Create the overlay window, floating icon, button behavior, and fallback
      activation gesture.

    Parameters
      None.

    Returns
      void.

    Guards
      - Returns if gOverlayWindow already exists.
      - Increments gInstallAttempts; returns after more than 40 attempts.
      - Returns if [UIApplication sharedApplication] is nil.

    Window selection
      - On iOS 13+, calls RAACHEATActiveWindowScene.
      - If a scene exists, creates the full-screen overlay with
        initWithWindowScene and the separate button window with
        initWithWindowScene.
      - If no scene exists but app.windows is non-empty, uses the legacy
        UIWindow initWithFrame fallback for the overlay and the button window
        (older apps that do not adopt UIScene).
      - If there is no scene and no app window yet, returns and retries.
      - On iOS 12 and older, creates frame-based UIWindows.

    Behavior
      - Sets the full-screen overlay to UIWindowLevelAlert + 100 and initially
        hides it (hidden = YES), so it cannot block game touches while closed.
      - Makes the overlay transparent.
      - Installs RAACHEATRootController and sets the root view frame.
      - Creates a separate 52x52 UIWindow at UIWindowLevelAlert + 101 for the
        floating button.
      - Creates RAACHEATButtonController as the button window's root.
      - Creates the 52x52 button and applies corner radius, border, clipping and
        accessibility label "Rxaa".
      - Loads menu_icon.png, then menu_image.jpg, as a background image.
      - Falls back to the letter "R" if no icon exists.
      - Adds a UIPanGestureRecognizer for -raacheatPan:.
      - Adds a single-tap gesture for -raacheatOpen. A drag does not open the
        menu; a tap does.
      - Restores the saved button-window position.
      - Calls RAACHEATInstallOpenGesture on the game host window.
      - Logs "[Rxaa] overlay installed ..." for diagnostics.

    Side effects
      Creates two UIWindows, a UIButton, and gesture recognizers in the current
      app process. No game process is modified. The full-screen menu window is
      hidden; only the 52x52 button window is visible until the menu opens.

27. RAACHEATTryInstall
    Signature: static void RAACHEATTryInstall(void)
    Location: Tweak.x

    Purpose
      Retry overlay installation when UIApplication or UIWindowScene is not
      ready yet, and reattach an existing overlay to the active scene.

    Parameters
      None.

    Returns
      void.

    Behavior
      - If gOverlayWindow exists, calls RAACHEATAttachWindowToScene.
      - If the window still has no UIWindowScene, schedules another attempt
        (up to the 41-attempt cap). This handles legacy windows that gain a
        scene late.
      - Calls RAACHEATInstallOverlay when no window exists.
      - If the window still does not exist, schedules itself again after
        1.5 seconds on the main queue.

    Side effects
      Repeated UI attempts until success or the 41-attempt cap.

    Parameters

PART 1B - CATALOG-DRIVEN FEATURE BROWSER
========================================
These functions/classes load menu_catalog.json and build the "All Features"
screen. The JSON is read from the installed resource directory, filtered to the
five feature categories, and displayed as grouped UI-only rows. If the JSON is
missing, malformed, or empty, an embedded 116-entry feature table is used
instead, so All Features is not empty in a sandboxed/unreadable-resource case.
No game process is contacted.

1. RXAACatalogCategories
   Signature: static NSArray<NSString *> *RXAACatalogCategories(void)
   Location: Tweak.x

   Purpose
     Define the category order used by the All Features screen.

   Returns
     @[@"aimbot", @"visuals", @"memory", @"settings", @"help"].

   Notes
     These are the categories counted as feature_entries in build_info.json
     (116 total).

2. RXAACatalogFeatures
   Signature: static NSArray<NSDictionary *> *RXAACatalogFeatures(void)
   Location: Tweak.x

   Purpose
     Load and cache the feature entries from menu_catalog.json.

   Behavior
     - Finds menu_catalog.json through RAACHEATResourcePath.
     - Reads it with NSData and NSJSONSerialization.
     - Reads the top-level "items" array.
     - Keeps dictionaries whose "category" is in RXAACatalogCategories.
     - Requires string values for "category" and "label".
     - If zero features were loaded, logs the missing path and calls
       RXAAEmbeddedCatalogFeatures for the built-in 116-entry fallback.
     - Caches the filtered/fallback array with dispatch_once.

   Returns
     The cached feature array. For this build it contains 116 entries even if
     the external JSON cannot be read.

   Notes
     The screen displays all 116 feature entries: 70 actionable entries
     (config-key/toggle/slider/combo) and 46 read-only label/help entries.

2a. RXAAEmbeddedFeature / kRXAAEmbeddedFeatures
    Signature: typedef struct {
                 const char *label;
                 const char *category;
                 const char *kind;

               static const RXAAEmbeddedFeature kRXAAEmbeddedFeatures[];
    Location: Tweak.x

    Purpose

      menu_catalog.json is unavailable.

    Contents

      - Only the fields used by the All Features UI are stored; no offsets,
        xrefs, meta flags, or memory addresses are embedded.

    Notes
      The table is generated from the same menu_catalog.json feature set. It is
      intentionally data-only and contains no game code.

PART 2 - INDEX.HTML JAVASCRIPT FUNCTIONS
========================================
The catalog is a self-contained page. MENU_DATA is embedded in the HTML.
All functions below are inside the IIFE near the bottom of index.html.

1. esc
   Signature: function esc(s)
   Location: index.html

   Purpose
     Convert a value to a safe display string.

   Parameters
     s - any value.

   Returns
     "" for null/undefined, otherwise String(s).

   Notes
     Defined but not used by the current renderer. The renderer uses
     textContent and createElement instead.

2. el
   Signature: function el(tag, cls, text)
   Location: index.html

   Purpose
     Create a DOM element with an optional class and text.

   Parameters
     tag  - HTML tag name.
     cls  - class name or null.
     text - optional textContent.

   Returns
     The new HTMLElement.

   Behavior
     Creates the element, sets className when provided, and sets textContent
     when the third argument is not undefined. Using textContent avoids HTML
     injection from catalog strings.

3. matches
   Signature: function matches(item)
   Location: index.html

   Purpose
     Decide whether a catalog item matches the active category and search
     query.

   Parameters
     item - one entry from MENU_DATA.items.

   Returns
     true if the item should be displayed, otherwise false.

   Behavior
     - "features" shows only aimbot, visuals, memory, settings and help.
     - "all" shows every item.
     - Any other active category shows only that category.
     - A non-empty query searches label, string address, first xref, kind,
       category and all xrefs.

4. copyText
   Signature: function copyText(text, done)
   Location: index.html

   Purpose
     Copy arbitrary text to the clipboard with a fallback for WKWebView/file://
     contexts where navigator.clipboard is unavailable.

   Parameters
     text - the text to copy.
     done - callback invoked after the copy attempt.

   Returns
     Nothing directly.

   Behavior
     - If navigator.clipboard.writeText exists, uses it and calls done on
       success.
     - On clipboard failure, or when the API is missing, creates a temporary
       textarea, selects it, calls document.execCommand("copy"), removes the
       textarea, and calls done.
     - This makes the "Get code" button work in the local WKWebView.

5. copyCard
   Signature: function copyCard(item, pre, ev)
   Location: index.html

   Purpose
     Copy one catalog entry and its assembly snippet to the clipboard.

   Parameters
     item - catalog item.
     pre  - the <pre> element containing the assembly.
     ev   - the click event, used to update the clicked button label.

   Returns
     Nothing directly; calls copyText asynchronously.

   Behavior
     - Builds a text block with label, string address, line number, xrefs,
       category, kind, flag/value/table/note metadata, and the assembly text.
     - Calls copyText.
     - On completion, changes the clicked button label to "copied" for 900 ms.

   Caveats
     - navigator.clipboard may be unavailable on file:// or in non-secure
       contexts; copyText provides the textarea/execCommand fallback.
     - The caller passes ev.currentTarget; the function no longer relies on the
       global event variable.

6. render
   Signature: function render()
   Location: index.html

   Purpose
     Rebuild the visible catalog card list.

   Parameters
     None (reads the closure variables active and query).

   Returns
     void.

   Behavior
     - Clears the list element.
     - Filters MENU_DATA.items with matches().
     - Updates the entry count.
     - Shows an empty-state message when nothing matches.
     - Builds cards with label, category/kind badges, addresses, metadata
       chips, and a collapsible <pre> assembly block.
     - Opens the AimLock card by default and up to the first two search
       results when searching in Features.
     - Adds a Get code button to each card.

   Side effects
     Replaces DOM nodes in #list. Does not mutate MENU_DATA.

7. buildCats
   Signature: function buildCats()
   Location: index.html

   Purpose
     Build the category filter buttons and their counts.

   Parameters
     None.

   Returns
     void.

   Behavior
     Iterates the category order (features, all, aimbot, visuals, memory,
     settings, help, ui, ui-id, runtime, path, format). Counts matching items,
     creates a button for each non-empty category, marks the active category,
     and attaches a click handler that updates active and calls render().

   Side effects
     Replaces children of #cats.

8. IIFE entry point
   Signature: (function(){ ... })()
   Location: index.html

   Purpose
     Initialize the catalog app.

   Behavior
     - Reads MENU_DATA and caches DOM elements.
     - Defines the functions above.
     - Wires the search input to update query and call render.
     - Calls buildCats() and render() once at startup.

   State
     active - current category, initially "features".
     query  - lowercased search string.

ANONYMOUS EVENT HANDLERS
------------------------
- Search input "input":
    query = value.trim().toLowerCase(); render().
- Category button "click":
    active = category; update active class; render().
- Get code button "click":
    calls copyCard(item, pre, ev).
- Card <details>:
    native HTML toggle; no JavaScript handler.

  then copies the result to packages/Rxaa.deb (or
  packages/Rxaa-rootless.deb when THEOS_PACKAGE_SCHEME=rootless).
  Not a function; not used by GitHub Actions.

layout/usr/bin/rxa-menu
  Shell launcher for mod_menu.py. It checks the rootful and /var/jb rootless
  Application Support paths, then runs python3 mod_menu.py --cli.

layout/Library/Application Support/RAACHEATMenuDebug/mod_menu.py
  Optional Python CLI/GUI config generator. It is not loaded by the tweak and
  does not hook or modify a game process.

.github/workflows/build-deb.yml
  GitHub Actions workflow:
    1. macOS runner.
    2. Install ldid/xz and Theos + iPhoneOS SDK.
    3. Build rootful package and copy it to out/rootful/Rxaa.deb.
    4. Build rootless package and copy it to out/rootless/Rxaa-rootless.deb
       (continue-on-error).
    5. Upload out/rootful/Rxaa.deb as the Rxaa-deb artifact.
    6. Upload out/rootless/Rxaa-rootless.deb as the Rxaa-rootless-deb
       artifact.

EXPECTED OUTPUT
---------------
Rootful:
  packages/Rxaa.deb

Rootless:
  packages/Rxaa-rootless.deb

INSTALL TARGETS
---------------
The tweak is filtered to apps linked against com.apple.UIKit.
Resources are installed under:
  /Library/Application Support/RAACHEATMenuDebug/       (rootful)
  /var/jb/Library/Application Support/RAACHEATMenuDebug/ (rootless)

LIMITATIONS
-----------
- The switches are UI-only. They do not perform AimLock/ESP/Radar actions.
- There are no game hooks, memory reads, memory writes, or offsets in this
  project.
- The floating button appears only in processes where the filter matches and
  UIApplication is available.
- The floating button position is persisted per app and clamped to the screen
  safe area. The full-screen overlay is hidden while the menu is closed, so game
  input is not blocked outside the 52x52 button window.
- While the menu is open, it intentionally captures game touches (it is a
  full-screen modal). Tap Close to return input to the game.
- The catalog does not make network requests.
- This documentation is static; the tweak was not compiled on the Windows
  workstation used to generate it.
